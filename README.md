# 重答与记忆撤销（0.1.1，实验版）

安装后产生的管理员私聊纯文本回复，可以在 5 分钟内用 `/重答` 移除当前对话中的上一轮用户输入及助手回复，用原问题重新生成，并取消该轮尚未提交的 AngelMemory 自动记忆整理。

## 仓库

https://github.com/ninthsister/astrbot_plugin_reply_redo

源码位于仓库根目录。修改后运行文末两组测试。仓库为私有时，AstrBot 不能在未授权情况下通过仓库 URL 克隆；可从 GitHub 的 Code → Download ZIP 下载后本地安装。

## 安装与使用

1. 先启用 `astrbot_plugin_angel_memory`，在 AstrBot 插件管理上传本插件 ZIP。
2. 重启 AstrBot，使两个插件都完成初始化；模型使用 AstrBot 内置 Agent。
3. 确认自己的 QQ 号已在 AstrBot 当前配置的管理员列表中。
4. 私聊发送一个纯文字问题，等待回复；不满意时在 300 秒内发送 `/重答`。
5. `/重答状态` 检查接入情况和上一轮状态。`pending` 才能撤销。关闭、重启、超时后不能撤销。

配置 `undo_seconds` 可调 30–1800 秒，改后重载本插件。指令前缀遵循 AstrBot 的配置。

## 指令

- `/撤销`：移除上一轮用户输入和助手回复、取消待提交记忆，不调用模型、不重新生成。撤销指令本身不作为新的用户轮次保存。
- `/重答`：执行相同撤销后，用原问题重新生成。
- `/重答状态`：检查接入和待提交状态。

两种操作沿用相同的权限、5 分钟窗口及历史校验。撤销后不能连续向前删除更早轮次。

## 原理和明确的行为变化

AngelMemory 当前源码会在 after_message_sent 中异步调用 plugin_manager.handle_memory_consolidation，然后将本轮记录放入后台反思缓冲。该插件没有公开的按轮次回滚 API。

本插件在运行时包装这一整理入口，对受保护的事件先延迟提交。窗口内 `/重答` 取消待提交任务，而不是从记忆库按关键词删除。窗口结束后才调用原始整理入口。由此避免误删其他用户或旧轮次的记忆，不直接操作 AngelMemory 数据库。

为防止模型绕开自动整理、直接持久化该轮内容，受保护请求会移除 `angel_remember` 和 `angel_note_create` 两个写工具，保留 `angel_recall` 等读取工具。移除仅限当前请求，不修改全局工具注册。管理员在此模式下要求模型立即“记住/写笔记”的工具行为会改变。

重答会重新走默认 Agent 流程；不把被拒绝的回复带进新提示。只允许管理员撤销自己在当前私聊会话的最后一轮；不会操作别的会话。会话切换、历史压缩、内容变化、出现额外轮次或工具调用时拒绝回滚，避免误删。已经执行的外部操作不能通过重答撤销。

## 范围和限制（安装前请阅读）

- **仅支持安装后产生的、管理员自己的原生私聊纯文本对话。** 不支持群聊、图片、音频和 AngelHeart 快照模式；这些轮次仍走 AngelMemory 原有逻辑。
- 只撤销尚未提交的本轮自动整理。不能追溯撤销安装前或窗口过期后已写入的记忆、人格变化、知识笔记，也不能消除第三方日志、其他插件的记录、模型供应商日志。
- 不撤回 QQ 已发出的消息气泡。“撤回记忆”是取消本轮待写入的整理。
- 若本轮调用了任何工具，历史检查通常会拒绝重答，因为工具可能已经产生外部副作用。内置重试、独立 Agent、子 Agent 直接写记忆或其他插件绕开此入口的写入不在保证范围内。
- 使用的是 AngelMemory 的内部方法，更新兼容性不能自动保证。核对源码为 `kawayiYokami/astrbot_plugin_angel_memory` 提交 `5439014cdb6126aa91bbcb915f922764a108c8c8`，metadata.yaml 标为 2.0.4（源码 register 装饰器仍是 1.3.37）。AstrBot 接口对照 v4.29.3。
- AngelMemory 热重载或入口被别的插件替换后，会停止接管新轮次，应重启 AstrBot。请在待提交窗口结束后再升级/重载 AngelMemory。
- 待提交记录保存在进程内，包含近期文本和事件引用；进程异常退出会丢失这些未提交记忆。正常卸载本插件会尝试提交仍待处理的记录并恢复原方法，随即失去撤销窗口。没有伪称已持久化的恢复机制。
- 记忆延后整理后，AngelMemory 自动反思看到这轮内容的时间也会延后。计时器不是严格的墙钟截止保证，实际以 pending/committing 状态为准。
- 模型重新生成也可能失败或仍不符合期待；旧轮次已经被移除，不承诺恢复原回答。

## 验证情况

已通过 9 项事务/历史校验测试及 5 项 AstrBot 接口替身契约测试，共 14 项：取消后不写入、超时仅提交一次、会话隔离、提交中拒绝回滚、正常卸载提交、工具副作用拒绝、历史变化拒绝，以及模拟请求→延迟记忆→撤销→重新发起请求。
